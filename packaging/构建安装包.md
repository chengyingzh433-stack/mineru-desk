# 构建安装包（不含大模型）

安装程序使用 Inno Setup 7 x64，包含客户端、MinerU、Python 与 CPU 依赖，支持选择安装目录。不附带 Pipeline/VLM 大模型、用户数据、缓存和 API 密钥。

## 准备运行环境

仓库只提供源码和打包脚本，不携带数 GB 的运行时目录。`npm run pack` 只生成 Electron 应用。完整安装包还需准备与发布版匹配的 Windows Python 依赖环境，以及合成测试文档。

`build_bundle.py` 接受 `--app`（解包后的 Electron 应用）、`--site-packages`（待分发依赖目录）、`--fixtures`（合成样例目录）、`--output`（不存在的目标目录）。它获取 CPython 3.12.10 embedded、复制依赖、应用 FastText 兼容补丁并保留许可；不会代为解析安装完整 Python 依赖集合。0.3.1 使用 MinerU 3.4.5 和 PyTorch 2.8.0+cpu，具体依赖以发行包的 `dependency-inventory.json` 为准。当前未提供跨机器逐字节可复现的锁定构建环境。

将干净的构建结果放到 `.build/runtime-bundle`，其中必须有 `runtime`、`examples`、`licenses` 和 `dependency-inventory.json`。该目录被 Git 忽略。不要从正在使用的工作区整体复制；模型和个人数据不能进入 staging。

## 编译

1. 确认 installer-marker.json 中 modelsIncluded=false，installer.iss 没有模型 payload 的 Files 项。
2. 确认上述运行时 staging 已准备好，版本与许可齐全。
3. `npm exec electron-builder -- --win dir --x64 --config packaging/installer-config.json`：只生成应用 staging，不运行 nsis。
4. `node packaging/create-manifest.mjs release-installer/win-unpacked`。
5. 用 Inno Setup 7 的 `ISCC.exe packaging/installer.iss` 编译。编译器官网下载后核验发布者签名；不随应用分发编译器。
6. 在隔离的中文路径实际安装，运行 `Codex.ps1 verify`、`doctor`、`self-test`。PDF 无模型时应返回 needs-models。单独导入已有模型做 PDF 验收，不能把测试模型混进包里。最后卸载，检查外部模型、配置和结果仍在。

不要将 ModelScope 缓存、模型、下载残片、data、output、Token 或用户论文作为发布源。模板内的安装前说明 TXT 是安装器说明文本，与 PDF 全文缓存无关。

Inno Setup 来源：https://jrsoftware.org/isdl.php 。安装包可选择目录，当前用户权限；模型与数据在安装目录外，升级、卸载不主动删除。
